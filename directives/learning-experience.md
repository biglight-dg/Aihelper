# AIHelper 학습 경험·설명·슬라이드 지침

## 목적

AIHelper의 강의, 커리큘럼, 실습, 화면 슬라이드를 비전공 초중급자가 혼자 따라갈 수 있는 하나의 학습 경험으로 유지한다.

## 대상과 문체

- 독자는 특정 분야를 처음 접하는 비전공 초중급자다.
- 중학생이 다시 읽지 않고 이해할 수 있는 문장 길이와 단어를 사용한다.
- 처음 나오는 전문용어는 쉬운 뜻과 구체적인 예시를 함께 제시한다.
- 감정적 격려, 과장, 막연한 성공 표현으로 설명이나 판정 기준을 대신하지 않는다.
- 실제 프로젝트 원본·빌드·운영 상태를 관찰하지 않았다면 예시를 실제 적용 결과라고 쓰지 않는다.

## 정보 구조

14개 분야는 과정 순서와 별개로 다음 네 개의 탐색 묶음을 제공한다.

| 묶음 | 분야 |
|---|---|
| 만들기 | 프론트엔드, 게임 개발, 앱 개발 |
| 알리기·성장 | 마케팅·성장, SNS·콘텐츠, 영업, SEO·GEO |
| 가르치기·언어 | 강의·교육, 언어 학습, 한국어 첨삭 |
| 검증·운영 | 평가·품질, 안전·권한, 프로젝트 운영, Second Brain |

첫 화면은 지식 문서 개수보다 위 네 묶음과 14개 강으로 가는 경로를 먼저 보여준다. 지식 베이스는 근거를 찾는 화면으로 유지한다.

## 한 강의 설명 계약

모든 강은 `배우기 → 예시 → 해보기 → 통과` 순서를 사용한다.

1. **배우기**: 이 강에서 해결할 문제, 핵심 원리, 용어의 쉬운 뜻을 설명한다.
2. **예시**: 상황·입력·처리·결과를 분리해 보여준다.
3. **해보기**: 학습자가 직접 만드는 산출물과 3단계 작업 순서를 제공한다.
4. **통과**: 퀴즈, 체크리스트, hard stop으로 결과를 판정한다.

공부 화면 상단에는 다음 세 정보를 먼저 보여준다.

- 이번 강 결과물
- 혼자 수행할 수 있어야 하는 학습 목표
- 설명과 판정의 순서

## 슬라이드 계약

- 한 장에는 하나의 주장이나 하나의 활동만 둔다.
- 제목은 `핵심 개념`, `작업 예시` 같은 분류명이 아니라 해당 장의 결론을 말한다.
- 제목 슬라이드는 과정명과 학습 경로만 남긴다.
- 본문을 줄여야 할 때는 글자 크기보다 문장 수와 반복 표현을 먼저 줄인다.
- 개념, 흐름, 예시, 실습, 통과 기준은 서로 다른 화면 형태를 사용한다.
- 상자, 배지, 그림자를 반복해 화면을 채우지 않는다. 구분선, 여백, 배경 면으로 구조를 먼저 만든다.
- 강의 화면 슬라이드는 1280×1600의 4:5 캔버스와 `validate_slides_data()`를 통과해야 한다.

## 화면 디자인 계약

- 기본 색은 AIHelper 보라색을 유지하되 그라데이션 장식보다 현재 위치와 다음 행동에 사용한다.
- 학습 홈의 14칸 지도는 실제 14개 강의 순서를 나타낼 때만 사용한다.
- 게임·마케팅·SNS 등 원하는 분야는 첫 화면에서 두 번 이내의 조작으로 열 수 있어야 한다.
- 키보드 초점, 모바일 적층, 긴 한글 제목, 빈 데이터, 로딩과 오류 상태를 확인한다.
- 다크 모드에서도 학습 단계 색과 본문 대비가 유지되어야 한다.

## 변경 후 검사

1. `scripts/build_phase4_learning_assets.py`를 dry-run과 격리 fixture에서 실행한다.
2. `scripts/verify_phase4_learning_assets.py`로 14강, 14실습, 14팁, 슬라이드와 앱 화면을 검사한다.
3. 학습 홈, 게임 6강 공부 모드, 실습·체크 화면을 데스크톱과 좁은 화면에서 직접 확인한다.
4. UI 파일을 수정했다면 Impeccable detector를 한 번 실행한다.
